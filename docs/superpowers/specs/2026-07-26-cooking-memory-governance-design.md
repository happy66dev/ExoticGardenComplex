# 烹饪模块内存治理设计

## 目标

在不改变正常烹饪、砧板交互与 AI 菜肴生成功能的前提下，消除烹饪模块长期运行时对 `World`、`Location`、`ArmorStand`、灶台状态与 HTTP 响应的无界内存持有。

## 范围

1. 仅在灶台发生有效状态变更后保留运行时状态；空闲空灶台自动回收。
2. 在灶台回收、区块/世界卸载与插件停用时，统一清理全息文本及位置缓存。
3. 在砧板所在世界卸载或插件停用时，移除展示盔甲架并释放砧板缓存。
4. 为 AI 请求增加有限并发数与响应大小限制；繁忙或响应异常时安全失败并释放槽位。
5. 构建、复制 jar，并用编译检查验证改动。

## 状态生命周期

- 玩家与灶台交互时维持既有处理器链路。
- 未发生任何有效交互的空灶台不会长期产生状态。
- 灶台变为空状态后不立即删除，以保留正常短暂连续操作；空闲达到既定时长后，由灶台 tick 任务清理状态、营火槽位与全息文本。
- 区块/世界卸载时立即清理该区域内运行时灶台状态及对应全息缓存，避免状态引用卸载世界。
- 插件停用时清理全部灶台全息、篝火槽位、灶台状态与静态全息缓存。

## 砧板生命周期

- 正常取回或破坏继续维持现有掉落、实体移除与 YAML 持久化行为。
- 世界卸载时移除该世界的展示盔甲架并从缓存删除，避免实体和世界引用残留。
- 插件停用时移除全部展示盔甲架并清空缓存；不额外改写 YAML，数据仍由现有保存流程持久化。

## AI 请求保护

- 使用共享有界信号量限制同时进行的 AI 请求。
- 无可用槽位时不发起网络请求，并向现有调用链返回明确的繁忙失败结果。
- 使用受限流读取成功与错误响应，超过最大字节数立即中止，拒绝解析超大 JSON。
- 所有成功、失败、超时、异常与取消路径均在 `finally` 释放并发槽位。

## 错误处理

- 空世界、已卸载区块、无效实体、空状态、HTTP 流读取失败及 JSON 解析失败均安全跳过或返回已有失败结果。
- 回收只处理无运行中 AI、无燃料、无食材、无调料的灶台，绝不回收仍有可见烹饪内容的状态。
- 清理过程只针对本插件标识的砧板展示实体，避免影响其他 ArmorStand。

## 验证

1. Maven 编译通过。
2. 执行 `copy_jars.bat` 生成部署 jar。
3. 人工核对：灶台短暂空闲后仍可继续操作；有内容的灶台不被清理；AI 并发满时安全提示；砧板取放与重启持久化不变。
